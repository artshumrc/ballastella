# One door to GitHub, and one badge

> **Amends [ADR-0032](./0032-publish-means-the-remote.md) and [ADR-0038](./0038-workspace-synchronization-is-explicit-and-baseline-based.md)** on where their gestures are reached from, and nothing about what they do.

The editor's bar carried eight elements about one question. In the eyebrow: a save badge, a Remote Status badge, *What this means*, *Check Remote Status*, *Update from GitHub*, and a "Checked at 14:22" line. In the main row: *Connect to GitHub* or *Connected to owner/repo*, and *Publish…*. The Workspace switcher's own header stated a third copy of the repository, the credential and the status in prose, and signing in was reachable from three places. Each of those was defensible where it stood and the sum was not: a scholar cannot tell which of five controls answers *is my work safe*.

**One entry point, and the gestures stay separate behind it.** A single control reports the standing state and opens one surface; **Publish** and **Update from GitHub** remain two presses there. A single *Sync* is refused, and the reason is not taste: a Publish mirrors an owned namespace and removes Projects the author deleted locally (ADR-0033), and an Update can remove work from the Workspace — `UpdateDeletionPreview` exists to name what. Those consequences differ in kind, so the author decides, and a verb that chose for them would choose in exactly the states where choosing matters. What is unified is the *place*, never the act.

**The door lands on whichever of three things is true**, read from the world rather than from a remembered position, as `ConnectToGitHub` already derives its step: this Workspace goes to that repository, that repository becomes a Workspace here, or send what has changed. The second is new as a *landing* and old as a mechanism — `openFromGitHub` has always done it, and ADR-0033's subset refusal has always pointed at it in words while offering no way there. A second machine binding to the repository its desktop published from was refused and told the remedy was Open a Workspace from GitHub, which lived in a settings dialog behind a field where the author typed `owner/repository` from memory. It is now a landing of the door that produced the refusal, offered whether or not the local Workspace is empty, because hydration overwrites nothing: it always makes a new browser-backed Workspace and leaves the current one alone.

**Opening a public Remote sits before the sign-in step**, because it is inbound and needs no credential — the story this transport is most likely to serve is a student seeding a Workspace from their instructor's site, and a door whose first step is signing in locks that student out of it. It accepts a Pages address, a GitHub address and `owner/repository`, resolving them to a candidate list and asking GitHub which candidate is real rather than asking the author: `ada.github.io/atlas` is `ada/atlas` or a folder inside `ada/ada.github.io` and no parser can tell. The identified repository is confirmed before a download that may run to gigabytes, and a custom domain is refused with the reason, since nothing can say which repository serves it. The ordinary route to the same place is the Published Site's own return link, which exists (`returnLinkUrl`, gated on the site's `editorUrl`) and was labelled with a term from the authors' glossary; a Reader is now offered **Open this Workspace in Ballastella** and **Open this Project in Ballastella**, neither promising Review or Import, because which of those happens is a choice the editor presents on arrival.

**One badge with two clauses, never one word.** *Saved here · not yet on GitHub.* The standing rule — that conflating local save state with Remote state is how a scholar comes to believe a saved edit is a published one — is kept where it does the work, in the text, and abandoned where it only cost height: two badges with two backgrounds side by side. The determination's own name, the sentence explaining it, the timestamp and the Synchronization Baseline's commit and file count all sit behind the disclosure the badge already has. Unbinding joins the door's connected step, and the uncorroborated legacy `remote.json` becomes a question asked once when it is true rather than a control sitting for ever in a dialog nobody opens — it always was a question, and it was filed where questions go unread.

**A credential may be kept past the tab, and only if the author asks.** `sessionStorage` remains the default, so the beneficiary of the original rule — a scholar on a shared or lab machine, whose credential must not outlive their tab — keeps that behaviour untouched. The rule narrows rather than falls: forgotten when the tab closes **unless the author has asked otherwise on this machine**. What persists is the refresh token and its expiry, never the eight-hour access token, and it lives outside every Workspace directory: `export-workspace-tar` walks a Workspace into a file the author mails to a colleague and a Publish uploads one to a public repository, so a credential anywhere inside one leaves the machine two ways that look like a favour (ADR-0033). `CredentialStore`'s three methods are unchanged, which is what its own header promised this swap would cost.
