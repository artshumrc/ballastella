Nav bar unification — 4 directions

The editor today is two rows inside one <header>: masthead (Workspace + save + theme, centered wordmark) above a ruled document row (breadcrumbs + Undo + Publish). The viewer is one row. All four below collapse the editor to one bar — a little taller than a single row, but ~16–28 px shorter than the current two. Every direction keeps the rule “it’s obvious what everything does” higher than “it looks nice”. Each includes desktop / tablet / mobile.

Current measured heights: two-tier ≈ 84 px (42 + 42). Single-row today (viewer) ≈ 46 px. Targets below: A 52 px, B 64 px, C 54 px, D 56 px. So regained vertical space vs today: A +32 px, B +20 px, C +30 px, D +28 px for the map.

A — One row, zoned 52 px • simplest

⬢ Zones: Workspace | Breadcrumbs left · Save · Undo · Publish · Theme right Wordmark: centered, hidden < 1024 px (as now) Mobile: breadcrumbs + Workspace stay, actions into overflow

One flex row with two dividers. No eyebrow, no tint. Clearest preservation of current grouping — the masthead facts and the document facts now sit side-by-side, separated by a rule. Closest to “just put it on one line”.

Why this works

  • Maximum space reclaimed (+32 px).
  • Information architecture unchanged — just closer.
  • Workspace stays fully visible and always first in tab order.
  • One row = one place to scan, no typographic hierarchy to learn.

Trade-offs

  • Long project names truncate sooner (breadcrumbs compete with Publish).
  • Save badge and Publish sit adjacent — could read as one group.
  • Centered wordmark still drifts if left/right clusters grow — current grid solved this; flex doesn’t.

B — Taller row with eyebrow 64 px • keeps hierarchy

⬢ Eyebrow 14 px: Workspace · save state · warnings (muted) Main row 50 px: Breadcrumbs · Undo · Publish · Theme

A single bar that’s a little taller, not two bars. The masthead facts become a small muted line above the main row — same signal as today, but 10 px not 42 px. Keeps the “what’s true of the Workspace vs what’s true of this screen” split without costing a full tier.

How to pick

  • If regaining height is the top job and clarity can’t slip: A.
  • If keeping today’s “Workspace facts vs screen facts” split matters most: B (pay 12 px more height than A).
  • If the left is too long today and you want the brand to do work: C — but reinstate a stronger Workspace affordance (maybe a subtle dot for Review copies).
  • If scanning is the bottleneck (“which controls are navigation vs work?”): D.
